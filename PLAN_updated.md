## 0. Known facts and open items

**[R1]** Known facts (documented in AGENTS.md; Step 1 validates them rather than rediscovering them):
- Files are in `input_data/` and follow `sampled_<YEAR>_<CLASS>_api.csv`, where `<CLASS>` is `benign` or `malware`. Each year has one file per class.
- Each file is a CSV with a header row, 1,500 rows and 1,849 columns. The first column is `apkname` (identifier); the other 1,848 columns are API-call features.
- Feature values are non-negative integer counts (not binary). No missing or non-numeric values were found in the files checked.
- The class comes from the file name: malware = 1, benign = 0. Malware is the positive class.
- Repeated `apkname` values exist within files (about 63-191 per 1,500 rows in the files checked).

Still unresolved:
- The exact year range (only 2019-2021 have been inspected). Step 1 discovers it from `input_data/` and records it in AGENTS.md.
- How many duplicate identifiers and duplicate feature vectors exist across all files and years (Step 1).

**Rule:** Step 1 validates the documented facts against all files and reports any mismatch. Nothing below hard-codes years, file names, or label strings; they come from the files and one config block in `src/config.py`.

## Year split policy (applies to every step)

Let the years be Y1 < Y2 < ... < Y8 (taken from the data, not assumed).

| Use | Years | Rule |
|---|---|---|
| Static training set (Steps 3-6) | Y1-Y4 (first half, fixed) | Fit all preprocessing, any feature selection, and models here only |
| Validation (model selection) | Inside Y1-Y4 only, using forward chaining (train on Y1..Yk, validate on Yk+1) | Never touches Y5-Y8 |
| Held-out test set (Steps 5-6) | Y5-Y8 | Used for final scoring only; report per year |
| Sustainable-approach experiments (Step 7) | Rolling: for each test year Yt, training data is limited to years before Yt | Test year is never in training |

**[R3]** The Y1-Y4 / Y5-Y8 split is fixed now, before any test-year drift results are examined. Step 2 may describe drift across all years, but test-year drift must not be used to choose the split boundary, select features, or tune model parameters. If the split ever has to change for a compelling reason, the reason and the decision are documented before any test results are used to guide it.

Leakage rules:
1. Scaler, feature selection, thresholds, and hyperparameters are fit on training years only.
2. **[R3]** Step 2 drift statistics use all years, but they are descriptive only. Test-year drift results must not be used to choose the split boundary, select features, or tune model parameters.
3. No shuffled random train/test split across years anywhere. A random split inside one year is only allowed as a labeled sanity baseline (and is reported as such, not as the main result).
4. **[R2]** Duplicates: Step 1 counts and reports two different things separately: (a) duplicate `apkname` identifiers, within each file and across years, and (b) identical feature vectors, within and across years. Identical feature vectors do not necessarily mean the same app. Nothing is removed silently: the counts are documented and the student decides before any row is dropped, especially for rows that appear in both training and test years.

## Step 1: Prepare the data

Approach
1. **[R1]** List `input_data/` to discover the year range, and validate the facts already documented in AGENTS.md (file-name pattern, 1,500 x 1,849 shape, header, integer counts, no missing values). Record the year range in AGENTS.md. Report any mismatch instead of silently adapting.
2. **[R2]** `load_file(path)`: read one file, check the shape is (1500, 1849), then separate `apkname` from the 1,848 feature columns and check the feature shape is (1500, 1848). `apkname` is kept as metadata for duplicate analysis but is never part of the model feature matrix.
3. `parse_filename(path)`: return `(year, label)` using a strict regex. Raise an error on any file that does not match, and never guess. Encode malware = 1, goodware = 0.
4. `build_dataset(input_dir)`: concatenate everything into one DataFrame with the 1,848 feature columns plus `label` and `year`, and `apkname` kept as a metadata column that is excluded from the feature matrix. Combine files per year, then across years. Column names must be identical across files (assert it).
5. Data-quality checks: missing values, non-numeric values, constant columns, malware share per year, and the two kinds of duplicates reported separately (duplicate `apkname` and identical feature vectors, each within files and across years; see leakage rule 4).

## Step 2: Handle data drift

Approach
1. **[R4]** Per-feature drift between years, designed for count-valued features (non-negative integer API-call counts, not binary): for each feature compare its distribution in each year with the first year and year-to-year, using:
   - The two-sample Kolmogorov-Smirnov statistic (the assignment's suggestion). Integer counts contain many ties, so the usual KS p-value calibration is only approximate; the report states this limitation and does not treat the p-values as exact.
   - Change in prevalence (share of apps with a nonzero count of the API call), which is easy to interpret.
   - A count-sensitive distribution distance, Jensen-Shannon distance (Wasserstein distance only if time permits).
   - Benjamini-Hochberg correction applied consistently, with the correction family stated: across the 1,848 features, separately for each year pair and class.
   - Effect sizes or distance values reported next to every significance result, not significance alone.
2. Year-by-year drift summary: number of significant features and mean KS statistic / mean distance for every pair of years, shown as a heatmap over all years; identify which years differ the most.
3. Top drifting features per year pair.
4. **[R4]** Class-conditional drift and temporal distinguishability: the same measures run separately for malware and benign apps (so a change in class mix over years is not read as feature drift), plus a "year classifier" check (how well a simple model can tell year A from year B). These show that the features change over time; they do not by themselves show concept drift (a change in the feature-label relationship). Possible concept drift is discussed in Step 6 alongside changes in predictive performance.

Files created
- `src/drift.py`, `results/step2_ks_matrix.csv`, `results/step2_top_features.csv`, `results/step2_drift_heatmap.png`
- `docs/step2_drift_analysis.md`: how drift was measured, features that drift most, years that differ most. Descriptive only: the Step 3 split is already fixed and is not changed by these results.

How it is tested
- Synthetic count data with known drift: identical distributions give a KS statistic and Jensen-Shannon distance near 0 and few significant features; a shifted feature is detected.
- Benjamini-Hochberg correction is applied within the stated family and adjusted p-values are never smaller than raw p-values.
- The result matrix is symmetric with a zero diagonal; the number of features is 1,848; p-values lie in [0, 1].
- No modification of the input dataframe (the function does not change data in place).
- `tests/step2_test_log.md`.

## Step 3: Preprocess data for model training

Approach
1. Split by year per the policy above: train = Y1-Y4, test = Y5-Y8. Return train and test as separate objects and keep the `year` column so later steps can report per year.
2. Remove the `label` and `year` columns from the feature matrix before scaling.
3. **[R5]** Every learned preprocessing operation (constant-feature removal and scaling) lives inside a scikit-learn `Pipeline`, so forward-chaining validation refits it on each fold's training years only. For example, in the fold that trains on Y1-Y3 and validates on Y4, nothing is fitted on Y4. After model selection, the final pipeline is fitted on all of Y1-Y4 and applied unchanged to Y5-Y8.
4. Scaling: `StandardScaler` for models that benefit from it (Logistic Regression, SVM, `SGDClassifier`). Features are integer counts with very different ranges, so scaling matters for these models. Random Forest does not need scaling, so models are not forced to share one scaling method; the choice per model and the reason go into the report.
5. Constant columns are dropped using training data only, and the same retained-feature set, in the same order, is applied to train and test data. Feature names and order are preserved.
6. Save the fitted pipeline and the list of kept features in `outputs/`.

Files created
- `src/preprocessing.py`, `results/step3_split_summary.csv` (rows and class balance per year and per split)
- `docs/step3_preprocessing.md`: scaling method, train/test years, how leakage is prevented.

How it is tested
- No year appears in both train and test; every test year is later than every training year.
- Scaler statistics (mean, scale) equal the training-set mean and standard deviation, not the whole dataset's. Changing the test data must not change the scaler.
- Train and test have the same feature columns in the same order; no `label` or `year` column in X.
- Row counts add up to the Step 1 total.
- **[R5]** Inside each forward-chaining fold, the fitted scaler statistics and the dropped-column set come from that fold's training years only (a validation-year change must not change them).
- `tests/step3_test_log.md`.

## Step 4: Apply machine learning classifiers

Approach
1. Models (scikit-learn): Logistic Regression (linear, fast, interpretable baseline), Random Forest (non-linear, robust to unscaled features, gives feature importance), and Linear SVM or Gradient Boosting as an optional third. Add `DummyClassifier(strategy="most_frequent")` as a floor baseline.
2. Hyperparameters: a small grid per model, chosen with forward-chaining validation inside Y1-Y4 (not random k-fold, which would mix years). **[R5]** Each model is wrapped in the Step 3 pipeline, so every fold fits its preprocessing on that fold's training years only; after selection the final pipeline is fitted on all of Y1-Y4. Fix `random_state=42`. Use `class_weight="balanced"` only if Step 1 shows a large imbalance.
3. Train each model on the training set; save the fitted model and its parameters.

Files created
- `src/models.py`, `outputs/models/*.joblib` (not committed), `results/step4_best_params.csv`
- `docs/step4_models.md`: classifiers, why chosen, hyperparameters, and how they were selected.

How it is tested
- Each model is a scikit-learn estimator that is fitted and can predict with the right output shape.
- Training uses only rows from the training years (check the training index against the years).
- Results are reproducible: two runs with `random_state=42` give identical predictions.
- Hyperparameter search folds respect time order (train years < validation year).
- `tests/step4_test_log.md`.

Approach

2. Metrics: accuracy (primary), and precision, recall, F1 with malware as the positive class (`pos_label=1`). Also report the confusion matrix and the dummy baseline. Use `zero_division=0` and say so.
3. Output one comparison table: rows = classifiers, columns = metrics. **[R7]** Metrics on the training set may also be reported, but they are labeled explicitly as in-sample results, kept in a separate table from the held-out test metrics, and never used for model selection or as evidence of future performance. Accuracy stays the primary metric, with precision, recall, and F1 as additional metrics.

Files created
- `src/evaluate.py`, `results/step5_metrics.csv`, `results/step5_confusion_matrices.csv`
- `docs/step5_evaluation.md`: table of accuracy, precision, recall, F1 for each classifier.

How it is tested

- The test set used is exactly the Y5-Y8 rows.

## Step 7: Sustainable ML approach

Approach: **[R6]** compare update strategies on the same rolling test years (Y5-Y8) using the *same underlying classifier* for every strategy, so differences can be attributed to the update strategy and not to a change of model. The classifier is an `SGDClassifier` (log loss, `random_state=42`, hyperparameters chosen with forward-chaining validation inside Y1-Y4), because it supports both full refitting and `partial_fit`.

| Strategy | Description |
|---|---|
| A. Static (never updated) | `SGDClassifier` trained on Y1-Y4, used for all test years |
| B. Periodic retraining, expanding window | Before testing year Yt, retrain from scratch on all years before Yt |
| C. Periodic retraining, sliding window | Retrain from scratch on the most recent W years before Yt (for example W = 2 or 3) |
| D. Incremental learning | Start from the strategy A model; call `partial_fit` with each year's labeled data after that year has been tested |
| Reference (not part of the controlled comparison) | The best Step 4 static model (Y1-Y4), shown separately and clearly labeled |

Rules and questions
- Always test on year Yt using only data from years before Yt (a "test-then-train" or prequential order).
- **[R6]** Scaling: the scaler is fitted once on Y1-Y4 and kept fixed for all strategies and test years, so the weights the classifier learned stay consistent with one feature transformation, and the only thing that differs between strategies is how the classifier is updated. Updating the scaler over time is not part of this design; if it is ever added, the plan must first say how consistency with the learned weights is kept.
- Label delay: assume the labels for year Yt become available only after year Yt, so the model for Yt+1 can use Yt. State this assumption in the report.
- Cost: record the training time and data size of each strategy so the report can discuss the accuracy vs. retraining cost trade-off.
- Optional, if time allows: retrain only when a drift or performance alarm fires (for example when the number of drifted features from Step 2 passes a threshold), compared with retraining every year.
- Window length W is chosen using only years up to Y4 or fixed in advance, not tuned on the test years. If W is explored, the tuning results are shown for all values (no cherry-picking).

Files created
- `src/sustainable.py`, `results/step7_strategy_comparison.csv`, `results/step7_strategy_by_year.png`
- `docs/step7_sustainable_approach.md`: approaches tried, comparison with the never-updated model, conclusions for the one-page report.

How it is tested
- For every strategy and test year, the training years are all strictly earlier than the test year (checked by recording the training years used).
- **[R6]** All strategies in the controlled comparison use the same classifier type and the same fixed scaler fitted on Y1-Y4 only.
- The separate Step 4 reference row reproduces the Step 5/6 numbers exactly.
- The sliding window uses exactly W years; the expanding window uses all earlier years.
- `partial_fit` runs on a year-by-year stream give the declared number of updates; results are reproducible with `random_state=42`.
- `tests/step7_test_log.md`.
