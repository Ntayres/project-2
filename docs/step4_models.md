# Step 4 Report: Classifiers and Training

Written by the builder agent. Generated by `python -m src.main --step 4`; all numbers come from code (`results/step4_best_params.csv`, `results/step4_cv_results.csv`; fitted models in `outputs/models/`).

## Classifiers chosen and why

Four scikit-learn estimators, trained on 2014, 2015, 2016, 2017 only:

**DummyClassifier.** Floor baseline. It predicts the most frequent training class and never reads the features, so it fixes the accuracy a model must beat before it can be said to have learned anything. With a 50/50 training set that floor is 0.50.

**LogisticRegression.** Linear, fast and interpretable baseline: one weight per API call, so the fitted model can be read. C sets the L2 regularisation strength, which is the parameter that matters with 1,105 correlated count features.

**SGDClassifier.** Linear model fitted by stochastic gradient descent. It is included because it supports partial_fit, so Step 7 can update it incrementally year by year and compare that with periodic retraining, using a model whose hyperparameters were selected here rather than one introduced late. loss='log_loss' keeps predict_proba available for threshold work in Step 5. alpha is its regularisation strength.

**RandomForestClassifier.** Non-linear and the natural contrast to the two linear models: it captures interactions between API calls, needs no scaling, and yields feature importances for the report. max_depth trades fit against variance; 200 trees are enough for a stable vote on 72,000 rows.

Three of them are real classifiers, which satisfies the assignment's "at least two"; the fourth is a baseline that cannot learn and exists to make the others' accuracy interpretable. One linear model, one linear model trained incrementally, and one non-linear ensemble give three different inductive biases on the same features.

## Hyperparameters and how they were selected

| classifier             | scaled   | grid searched                                               | chosen                                   |
|:-----------------------|:---------|:------------------------------------------------------------|:-----------------------------------------|
| DummyClassifier        | no       | none (no hyperparameter to choose)                          | defaults                                 |
| LogisticRegression     | yes      | C in {0.01, 0.1, 1.0, 10.0, 100.0}                          | {'C': 10.0}                              |
| SGDClassifier          | yes      | alpha in {1e-06, 1e-05, 0.0001, 0.001, 0.01}                | {'alpha': 1e-06}                         |
| RandomForestClassifier | no       | max_depth in {10, 20, 40, None}, min_samples_leaf in {1, 5} | {'max_depth': 40, 'min_samples_leaf': 1} |

The grids are small on purpose (PLAN.md Step 4): for each model, a few values of the one parameter that matters most on 1,105 correlated count features, so the selection is measured rather than asserted and still finishes in a single run. Everything else is left at the documented value in the estimator call, and `random_state=42` is fixed everywhere.

Selection used **forward-chaining validation inside the training years only**, never random k-fold, which would let a fold train on a year it validates on:

  1. train on 2014 -> validate on 2015
  2. train on 2014, 2015 -> validate on 2016
  3. train on 2014, 2015, 2016 -> validate on 2017

Each fold refits the whole pipeline - the dropped-column set, the scaler and the classifier - on that fold's training years, and only transforms its validation year. The 4 test years (2018, 2019, 2020, 2021) take no part: they are not loaded into the search, not scored, and not used to pick anything. After the search, scikit-learn refits the winning configuration on all 72,000 training rows, and that is the model saved for Step 5.

**Selection metric.** Accuracy, because the assignment names it the primary metric. Precision, recall, F1 and ROC AUC are computed on the same folds and reported beside it, so a model that bought accuracy by neglecting one class is visible here rather than only in Step 5. Malware (label 1) is the positive class.

**Class weights.** not used. Every training year is exactly 50% malware (Step 1 and Step 3), so there is no imbalance to correct; `class_weight='balanced'` would leave the weights unchanged. PLAN.md only calls for it if Step 1 shows a large imbalance.

### Did the grids bracket the chosen values?

A value chosen at an end of its grid may not be the best value, only the best of those searched. This is checked automatically for every searched parameter:

- **LogisticRegression** chose `C=10.0` from {0.01, 0.1, 1.0, 10.0, 100.0}, an interior value, so the search bracketed the optimum on this parameter.
- **SGDClassifier** chose `alpha=1e-06`, the **lowest** value searched in {1e-06, 1e-05, 0.0001, 0.001, 0.01}, so a better value may lie below the grid and this result should be read as a grid-edge selection.
- **RandomForestClassifier** chose `max_depth=40` from {10, 20, 40, unbounded}, an interior value, so the search bracketed the optimum on this parameter.
- **RandomForestClassifier** chose `min_samples_leaf=1` from {1, 5}. That is the limit of this parameter, so no value beyond it exists to search; the other values scored worse. Not a grid-edge concern.

## What this step does not do

- **No test-year data is touched.** No model is scored on 2018, 2019, 2020, 2021 here; that is Step 5 (overall metrics) and Step 6 (per year). Reporting a test score in this step would make the selection above unusable, because the choice would then depend on the data it is meant to be judged on.
- **No threshold tuning.** All metrics use each model's default decision rule. Moving a threshold to trade precision against recall is a Step 5 question, and it would have to be chosen on training-year folds, not on test years.
- **No feature selection beyond Step 3's constant-column removal**, which was fitted on training years and is refitted per fold.

## Checks run on this step

- **Folds stay inside the training years and keep the time order.** `check_folds` confirms that no fold reaches a year outside 2014, 2015, 2016, 2017, that each fold's validation year is later than every year it trains on, and that no row is in both halves of a fold. *Establishes:* model selection saw no test-year row. *Does not establish:* anything about the final refit, which is on the whole training half by design.
- **The chosen configurations are reproducible.** Each selected pipeline was cloned and fitted twice on the same 4,000-row training subsample; identical predictions for 4 of 4 models. *Establishes:* the seeds fix the fit for the configuration actually chosen. *Does not establish:* that a different machine or library version reproduces the same numbers.
- **Training rows only.** The matrices come from Step 3's `features_labels` on the training frame, whose years and labels were checked by `check_labels_years` before any fitting.

## Files written

- `results/step4_best_params.csv`: the chosen configuration per model, its CV scores per metric, per-fold accuracy, fit time and the reproducibility result.
- `results/step4_cv_results.csv`: every grid candidate with all five metrics.
- `outputs/models/<classifier>.joblib`: each winning pipeline fitted on the full training half (preprocessing and classifier together, so Step 5 applies exactly what was fitted).

## What Step 5 uses from here

The saved pipelines are the trained models to score. Step 5 loads each one, calls `predict` (and `predict_proba` where available) on the test years returned by `preprocessing.split_by_year`, and reports accuracy, precision, recall and F1 with malware as the positive class. The pipelines already contain their own preprocessing, so Step 5 must not transform the test data itself.
